# Voice signaling qualification

This is an isolated transport proof against configured LiveKit 1.12.0 Standard/protocol 17. The browser uses a consumed opaque ticket; the independent backend worker retains reusable SFU credentials and filters refreshed tokens. Generated audio publishes, cached tickets fail through both relay and direct SFU, staff-policy simulation disconnects an old binding, and a fresh listen-only binding survives historical revocation. Altering SDK permission flags still produces a backend protocol rejection. An independent RoomService witness observes the provider participant absent after the worker deadline while the gateway event loop remains blocked. All generated audio contexts close and the uniquely named room is deleted, with absence checked. There are no school database writes, user microphones, recording, or deployment.

Seven protocol/socket tests and strict service types pass. The archived source matches those tests and the passing provider run. Attempts 1–5 are retained negative reports/logs from earlier source revisions; they are not claimed to match the archived source. Provider HTTP 400 exposed stripped URL-safe base64 padding; the installed SDK preserves padding, and the fix covers every encoded-length residue. Earlier probes also revealed insufficient failure diagnostics and a probe attempting audio publication after failed initial connection.

This archive does not qualify school Auth, SQL media policy, product UI/reconnect, hidden-observer privacy, physical/mobile audio devices, load, outages, deployment or a matched game release. A provider participant disappearing proves that this owned signaling connection ended; it is not a bound for whole-host loss or total upstream network isolation. The prior cached-SFU-token bypass baseline remains in voice-provider-baseline.
